# 人工 Smoke Checklist

本文档用于正式重构前后对照，确认核心功能没有回退。当前项目以 Tauri 桌面端为运行入口，桌面前端由 `npm.cmd run prepare:desktop` 生成。

## 使用方式

1. 运行 `npm.cmd run desktop:dev` 打开桌面端。
2. 先导出一份当前 JSON 备份。
3. 按下面清单逐项操作。
4. 每轮正式重构后重复执行同一清单。
5. 如某项失败，记录浏览器、操作步骤、当前页面、控制台错误和是否使用导入数据。

## 今日训练

- [ ] 能打开首页，默认进入“今日训练”。
- [ ] 能在“今天在哪个健身房”下拉框中选择当前健身房。
- [ ] 切换当前健身房后，顶部状态和当前场地摘要会更新。
- [ ] 点击“生成/刷新计划”后能生成训练计划。
- [ ] 能在“训练日”下拉框中选择不同训练日。
- [ ] 能看到今日训练动作表格。
- [ ] 每个动作能显示动作名称、组数、次数 / 时长、重量、RPE、休息、备注 / 替代和示例链接。
- [ ] 能保存训练整体反馈：完成度、平均 RPE、疼痛、睡眠、疲劳和备注。
- [ ] 保存训练整体反馈后能跳转或显示智能建议。
- [ ] 能保存动作级反馈：实际重量、实际次数、RPE、质量、幅度、目标肌肉感觉、限制因素、左右差、疼痛和自由文本。
- [ ] 可选填写每组记录，保存后能在动作反馈列表或历史中看到容量、有效组或 PR 信息。
- [ ] 保存动作级反馈后能生成对应智能建议。
- [ ] 动作级反馈能在近期列表或智能教练历史中看到。

## 目标设定

- [ ] 能输入自然语言目标。
- [ ] 能解析减脂目标，例如“我现在 78kg，想减脂到 72kg”。
- [ ] 能解析增肌目标，例如“想增肌，每周练 4 次”。
- [ ] 能解析力量目标，例如“想提高深蹲卧推力量”。
- [ ] 能解析出差约束，例如“最近经常出差”。
- [ ] 能解析每周训练次数，例如“一周练 3 次”。
- [ ] 能解析单次训练时长，例如“每次 45 分钟”。
- [ ] 能保存目标。
- [ ] 能把某个目标设为当前目标。
- [ ] 当前目标能影响后续训练计划生成的目标标签、训练天数或训练口径。

## 核心业务链路

### 链路 1：从目标到计划

- [ ] 输入目标。
- [ ] 解析目标。
- [ ] 保存并设为当前目标。
- [ ] 选择当前健身房。
- [ ] 生成计划。
- [ ] 计划上下文显示目标和健身房。

### 链路 2：从训练到建议

- [ ] 生成计划。
- [ ] 在今日训练中选择训练日。
- [ ] 保存训练整体反馈。
- [ ] 保存至少一条动作级反馈。
- [ ] 智能教练出现训练建议和动作建议。
- [ ] 如果反馈包含疼痛或完成度低，能出现 revision 候选。

### 链路 3：从饮食到联动判断

- [ ] 保存至少一条饮食记录。
- [ ] 饮食记录产生营养估算和建议。
- [ ] 饮食长期画像能读取该记录。
- [ ] 今日建议或周复盘能结合饮食记录产生联动判断。

### 链路 4：备份恢复

- [ ] 完成一轮目标、计划、训练、动作反馈、饮食记录。
- [ ] 导出 JSON。
- [ ] 恢复初始数据。
- [ ] 导入刚才导出的 JSON。
- [ ] 页面能恢复主要数据并正常渲染。

## 不应发生的回退

- [ ] 不能要求安装依赖才能打开应用。
- [ ] 不能要求启动服务才能使用基础功能。
- [ ] 不能破坏 Tauri 桌面端启动和 `dist/desktop` 前端资源生成。
- [ ] AI 或规则不能静默修改计划。
- [ ] JSON 导入不能导致页面空白。
- [ ] CSV 导入不能导致计划页崩溃。
