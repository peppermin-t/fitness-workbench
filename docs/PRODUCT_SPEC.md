# 个人智能训练工作台产品规格

## 1. 产品目标

本产品是一个电脑端、本地优先的个人训练与饮食决策工具，用来替代教练用 Excel 管理训练计划的方式，并补上智能化的计划制定、执行反馈、计划优化、动作示例和饮食判断。

最高目标：

```text
用最少录入成本，把训练、饮食、身体变化和出差场地限制串起来，
持续给出可解释、可确认、可执行的个人训练与饮食调整建议。
```

产品不追求社交、课程平台或复杂账号体系。核心是便利化个人使用：快速录入、稳定保存、清楚解释、逐步了解用户。

## 2. 用户场景

1. 用户经常出差，不同健身房器械不同，训练计划必须能按当前场地调整。
2. 用户原先由教练用 Excel 管理训练计划，现在希望电脑端工具承接计划、记录和复盘。
3. 用户每次训练后会反馈动作细节，例如“左侧最后几个半程”“练背小臂先酸了”“卧推肩前侧不舒服”。
4. 用户会不定期录入体重、体脂、骨骼肌、腰围等身体指标，并希望计划考虑这些趋势。
5. 用户希望用自然语言记录目标和饮食，例如“想减脂到 72kg，但不想掉力量”“早上吃了 5 个蛋白，一个地瓜，一碗豆浆”。

## 3. 产品边界

### 3.1 第一阶段内要做

- 本地电脑端可用。
- 健身房/场地器械管理。
- 动作库、动作示例链接、替代动作。
- 自然语言目标解析。
- 训练计划生成和 CSV 导入/导出。
- 身体指标时间线。
- 训练日整体反馈。
- 动作级完成细节反馈。
- 饮食自然语言记录。
- 本地规则生成训练和饮食建议。
- JSON 备份/恢复。

### 3.2 后续可做

- Tauri 桌面打包。
- SQLite 本地数据库。
- `.xlsx` 直接导入。
- 动作库和食物库编辑。
- OpenAI 结构化输出解析训练反馈和饮食记录。
- 长期动作画像和饮食画像。
- 训练、饮食、身体指标联动分析。

### 3.3 明确不做

- 不做社区。
- 不做公开课程平台。
- 不做医学诊断。
- 不做视频动作识别。
- 不做自动医疗/康复处方。
- 不让 AI 绕过规则引擎直接静默修改计划。
- 不要求每次训练录入过重，普通训练后应能在 2-3 分钟内完成反馈。

## 4. 核心模块

### 4.1 目标设定

用户可以用自然语言录入目标：

```text
我现在 78kg，想先减到 72kg，但不想掉太多力量。
最近经常出差，一周练 3 次，每次 45 分钟。
```

系统解析为结构化目标：

```json
{
  "primaryGoal": "fat_loss",
  "secondaryGoal": "strength_maintenance",
  "targetWeight": 72,
  "trainingDaysPerWeek": 3,
  "sessionDurationMinutes": 45,
  "constraints": ["frequent_travel"]
}
```

目标会参与训练计划生成、饮食判断和周复盘。

### 4.2 健身房/场地

每个健身房维护自己的器械范围：

- 名称
- 地点/备注
- 可用器械
- 是否当前场地

生成替代动作时必须受当前场地器械约束。例如酒店健身房没有深蹲架时，不应推荐杠铃深蹲。

### 4.3 动作库

每个动作包含：

- 动作名称
- 动作模式
- 目标肌群
- 必需器械
- 替代动作
- 技术提示
- 风险提示
- 示例链接

动作库是计划生成、替代动作和动作级反馈判断的基础。

### 4.4 身体指标

记录不定期测量数据：

- 体重
- 体脂率
- 骨骼肌
- 腰围
- 备注

系统展示时间趋势，并在计划和饮食建议中考虑趋势。例如减脂目标下体重长期不变，需要检查饮食和有氧；增肌目标下体重长期不变，需要检查热量和蛋白。

### 4.5 训练计划

计划结构：

```text
计划 -> 训练日 -> 动作 -> 组数/次数/重量/RPE/休息/备注
```

计划生成依据：

- 当前目标
- 当前健身房器械
- 最近身体指标
- 最近训练反馈
- 动作库替代关系

### 4.6 动作级反馈

每个动作需要支持结构化反馈和自然语言反馈。

结构化字段：

```text
实际重量
实际次数
RPE
动作质量：好 / 一般 / 差
动作幅度：完整 / 后程半程 / 全程半程
目标肌肉感觉：强 / 中 / 弱 / 没感觉
限制因素：目标肌肉 / 小臂握力 / 关节疼 / 核心不稳 / 心肺 / 疲劳 / 技术
左右差异：无 / 左弱 / 右弱
疼痛评分
疼痛部位
自由反馈
```

自然语言示例：

```text
左侧最后几个半程，小臂先酸了，背没什么感觉。
```

系统应解析为：

```json
{
  "tags": ["left_weaker", "reduced_rom_late", "grip_limiting", "poor_target_muscle_feel"],
  "severity": "medium"
}
```

### 4.7 饮食自然语言记录

用户可以用一句话记录当天饮食：

```text
早上吃了5个鸡蛋蛋白一个地瓜一碗豆浆一点炒面，
中午没吃饭吃了四个威化，
晚上吃了牛肉火锅。
```

系统解析餐次、食物、模糊分量和标签：

```json
{
  "meals": [
    {
      "meal": "breakfast",
      "items": ["5个鸡蛋蛋白", "1个地瓜", "1碗豆浆", "一点炒面"],
      "tags": ["high_protein", "mixed_carbs", "portion_uncertain"]
    },
    {
      "meal": "lunch",
      "items": ["4个威化"],
      "tags": ["missed_meal", "processed_snack", "low_protein", "high_sugar_possible"]
    },
    {
      "meal": "dinner",
      "items": ["牛肉火锅"],
      "tags": ["high_protein", "high_fat_possible", "high_sodium_possible", "portion_uncertain"]
    }
  ],
  "confidence": "medium_low"
}
```

饮食建议不追求精确医学营养处方，第一版只做估算和结构判断：

- 蛋白是否可能不足
- 正餐是否缺失
- 高糖零食是否替代正餐
- 外食油脂/钠是否可能偏高
- 碳水是否支持训练
- 当前目标下是否需要调整

## 5. 智能规则边界

### 5.1 训练建议规则

```text
完成目标次数 + RPE <= 7 + 无疼痛 + 动作质量好
=> 下次可加重 2.5%-5% 或增加 1-2 次
```

```text
出现后程半程 + RPE >= 9
=> 下次不加重，必要时降重 5%-10%，先恢复完整幅度
```

```text
左侧/右侧弱
=> 弱侧先做，以弱侧高质量完成次数决定另一侧次数
```

```text
练背时小臂先酸 + 背部感觉弱
=> 判断为握力限制或背部募集不足，建议助力带、稳定划船、直臂下拉激活
```

```text
疼痛评分 >= 3
=> 不建议加重，生成替代动作或降量建议
```

### 5.2 饮食建议规则

减脂：

```text
漏正餐或用零食替代正餐
=> 提醒晚餐过量风险，建议补高蛋白简餐
```

```text
火锅/炒面/威化等高油高糖高钠项集中
=> 提醒热量和钠不确定性，建议控制油脂蘸料和主食量
```

增肌：

```text
午餐蛋白不足
=> 建议增加便携蛋白来源
```

```text
训练日碳水不足
=> 建议训练前后补稳定碳水
```

出差维持：

```text
优先保证每餐一个蛋白来源 + 一个主食/薯类 + 一份蔬果或蔬菜
```

## 7. 阶段设计与验收标准

### 阶段 0：本地工作台 MVP

目标：先有一个能打开、能记录、能生成计划的本地工作台。

已包含：

- 本地静态页面
- 目标设定
- 健身房器械
- 身体指标
- 动作库
- 训练计划生成
- 训练日整体反馈
- 基础建议
- CSV/JSON 导入导出

验收标准：

- 双击 `index.html` 可使用。
- 能录入目标、健身房、身体指标。
- 能按当前健身房生成训练计划。
- 能保存一次训练后的整体反馈。
- 能生成基础调整建议。

当前状态：已完成。

### 阶段 1：动作级训练反馈

目标：从“今天练得怎么样”升级为“每个动作具体做得怎么样”。

要做：

- 每个动作填写实际重量、次数、RPE。
- 记录动作质量、动作幅度、目标肌肉感觉、限制因素、左右差、疼痛。
- 支持每个动作自由文本反馈。
- 保存动作级历史。

验收标准：

- 今日训练页每个动作都有反馈入口。
- 一次训练结束后能保存动作级记录。
- 能在历史中回看每个动作的问题。
- 普通训练后 2-3 分钟能完成录入。

当前状态：基础入口已实现。已支持动作级结构化反馈、自由文本反馈、本地标签识别和动作建议；后续需要补动作历史页、长期动作画像和计划级联动。

### 阶段 2：饮食自然语言记录

目标：用一句话记录当天饮食，并生成结构化判断。

要做：

- 饮食记录入口。
- 自然语言解析早餐/午餐/晚餐/加餐。
- 识别食物、数量、模糊分量。
- 输出饮食标签、置信度和建议。
- 保存每日饮食记录。

验收标准：

- 能解析“5个蛋白、一个地瓜、一碗豆浆、四个威化、牛肉火锅”。
- 能识别漏餐、零食替代正餐、高蛋白、高油脂、高钠、蔬菜不足。
- 能针对减脂/增肌/出差目标输出不同建议。
- 能保存和回看饮食记录。

当前状态：基础入口已实现。已支持自然语言饮食记录、本地餐次拆分、饮食标签、置信度和目标相关建议；后续需要补饮食趋势、食物库和长期饮食画像。

### 阶段 3：本地规则建议引擎

目标：训练反馈和饮食记录都能生成基础建议。

验收标准：

- “左侧最后几个半程”能触发不加重、弱侧先做、必要时降重。
- “练背小臂先酸，背没感觉”能触发握力限制、助力带、激活动作建议。
- “卧推肩前侧不舒服”能触发不加重、降强度或替代动作。
- 饮食能判断正餐缺失、蛋白不足、火锅/零食导致的不确定性。

当前状态：基础规则已实现。已支持训练整体反馈、动作级反馈、饮食结构判断以及写入智能建议；后续需要补计划级联动、周复盘和优先级管理。

### 阶段 3.5：画像与联动基础

目标：把动作级反馈和饮食记录聚合成长期画像，并接入首页判断。

验收标准：

- 能生成动作长期画像，识别高频问题动作。
- 能生成饮食长期画像，识别漏正餐、零食替代、纤维不足和外食不确定性。
- 首页“今日建议”能同时读取训练、饮食和身体指标给出联动判断。
- 智能教练页能直接查看画像，而不是只看单条反馈。

当前状态：已完成基础版。

### 阶段 4：训练 + 饮食 + 身体指标联动

目标：把训练表现、饮食结构和身体变化联合分析。

验收标准：

- 体重 2-3 周不变时，能结合饮食记录判断可能原因。
- 训练 RPE 升高且午餐经常缺失时，能提示供能不足。
- 减脂期力量明显下降时，能提醒蛋白和恢复风险。

当前状态：未完成。

### 阶段 5：长期画像

目标：系统越用越了解用户。

验收标准：

- 能生成动作长期问题画像。
- 能生成饮食长期问题画像。
- 下次训练或饮食记录前能提前提醒，而不是只事后总结。

当前状态：未完成。

### 阶段 6：AI 结构化解析

目标：用 AI 理解更复杂、更口语化的训练和饮食反馈。

验收标准：

- AI 输出固定 JSON。
- JSON 校验后再进入规则引擎。
- 断网时能用本地关键词解析降级。
- AI 不直接静默改训练计划。

当前状态：未完成。

### 阶段 7：正式桌面应用

目标：从静态页面升级为正式本地桌面应用。

要做：

- Tauri 桌面壳
- SQLite 数据库
- `.xlsx` 直接导入
- 自动备份
- 数据迁移

验收标准：

- 能作为桌面应用启动。
- 数据不依赖浏览器 localStorage。
- 能导入教练 Excel。
- 能备份和恢复完整训练/饮食数据。

当前状态：未完成。

## 8. 当前项目位置

当前已经完成阶段 0，并完成了阶段 1、阶段 2 的基础入口，以及阶段 3.5 的基础版。

下一步推进顺序：

```text
阶段 4：训练 + 饮食 + 身体指标联动
阶段 5：长期画像深化
阶段 6：AI 结构化解析
```

原因：动作级反馈和饮食记录是后续智能判断的数据入口。没有这两个入口，AI 或高级分析都没有足够可靠的数据基础。
